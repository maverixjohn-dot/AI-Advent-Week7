# Ассистент разработчика 1С («Целеполагание»)

Локальный помощник разработчика конфигурации 1С. Работает поверх XML-выгрузки
конфигурации (формат конфигуратора, иерархический), объединяя:

- **RAG** по документации проекта, карточкам объектов метаданных и текстам модулей (bsl);
- **MCP-сервер** с инструментами доступа к проекту (git-ветка, diff, файлы,
  дерево объектов, состав объекта, поиск);
- **Чат-интерфейс** на Flet (светлая тема, оранжевый + серый) со страницей
  администрирования: статистика индекса, переиндексация, просмотр логов;
- **LLM DeepSeek** для ответов на свободные вопросы (function calling по
  инструментам MCP).

Slash-команды выполняются детерминированно, без обращения к LLM (мгновенно и
без расхода токенов). Свободный текст — через DeepSeek, который сам выбирает
нужные инструменты.

## Команды

| Команда | Что делает |
|---|---|
| `/help` | Справка по командам |
| `/tree` | Дерево объектов конфигурации по подсистемам |
| `/object <имя>` | Состав объекта: реквизиты, табличные части, формы, модули. Пример: `/object ФинансовыйФакт` |
| `/objects [маска] [тип=...] [подсистема=...]` | Объекты по фильтру. Примеры: `/objects *Финанс*`, `/objects тип=Документ` |
| `/branch` | Текущая ветка git репозитория выгрузки |
| `/diff [файл]` | Изменения в рабочем дереве (целиком или по файлу) |
| `/reindex [full]` | Переиндексация RAG (инкрементальная по умолчанию, `full` — полная) |

## Требования

- Python 3.10+ (проверено на 3.12), ОС Linux/Windows/macOS;
- ~4 ГБ свободной RAM под модель эмбеддингов `intfloat/multilingual-e5-large`
  (CPU достаточно при текущем объёме проекта);
- ~2 ГБ на диске под модель эмбеддингов и зависимости;
- доступ к api.deepseek.com (для свободных вопросов; slash-команды работают и без него).

## Установка

```bash
cd assistant-1c
python -m venv .venv
source .venv/bin/activate          # Linux/macOS
.\.venv\Scripts\Activate.ps1       # Windows PowerShell (cmd: .venv\Scripts\activate.bat)
pip install -r requirements.txt
```

Вместо активации можно вызывать интерпретатор напрямую:
`.\.venv\Scripts\python ...` (Windows) или `.venv/bin/python ...` (Linux/macOS).
Если PowerShell блокирует скрипт активации политикой выполнения:
`Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`.

Если torch ставится с CUDA (лишние ~2 ГБ), вместо последней строки:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

Flet при первом запуске сам доустанавливает пакет `flet-desktop` (или
`flet-web` для web-режима) — нужен доступ к PyPI.

## Настройка

Все параметры читаются из переменных окружения процесса. Файл `.env` —
необязательный способ задать те переменные, которых в окружении нет: он
подхватывается через python-dotenv, при этом уже существующие переменные
окружения приоритетнее и значениями из файла не перекрываются.

Если `DEEPSEEK_API_KEY` уже задан в переменных окружения — никуда вписывать
его не нужно, код возьмёт значение напрямую из окружения. Тогда остаётся
задать только путь к выгрузке — любым способом:

```bash
export A1C_DUMP_ROOT=/полный/путь/к/LifeProgect
```

или через `.env` (одна строка `A1C_DUMP_ROOT=...`):

```bash
cp .env.example .env
```

Переменная окружения должна быть видна процессу, который запускает
приложение: для systemd — через `EnvironmentFile=`/`Environment=` в
unit-файле; в Windows после установки переменной перезапустите терминал/IDE.

Остальное — по необходимости (см. комментарии в `.env.example`):
модель (`DEEPSEEK_MODEL=deepseek-v4-pro`), режим рассуждения
(`DEEPSEEK_THINKING=1`), модель эмбеддингов, глубина RAG-выдачи.

Если huggingface.co недоступен из вашей сети, перед первой индексацией:

```bash
export HF_ENDPOINT=https://hf-mirror.com
```

## Подготовка репозитория выгрузки

Команды `/branch` и `/diff` требуют, чтобы выгрузка была git-репозиторием:

```bash
cd /полный/путь/к/LifeProgect
git init -b main
git config user.name "Ваше Имя"
git config user.email "you@example.com"
git add -A && git commit -m "Выгрузка конфигурации"
```

Без репозитория ассистент работает, но git-инструменты вернут ошибку.

## Первый запуск

```bash
# 1. Полная индексация (первый раз скачает модель эмбеддингов ~2 ГБ)
python -m indexer.indexer --full

# 2. Запуск UI
python main.py                 # десктопное окно
python main.py --web           # браузер, http://localhost:8550
```

Индексацию можно делать и из интерфейса: страница «Админ» → кнопки
переиндексации, там же статистика и логи.

## Пополнение RAG документацией

Индексируются автоматически:

1. `README.md` и все `.md` из `docs/` внутри репозитория выгрузки —
   сюда же позже добавляются файлы требований к код-ревью и прочая документация;
2. карточки всех объектов метаданных (генерируются из XML);
3. тексты модулей (`.bsl`) — по процедурам/функциям с учётом областей.

После добавления файлов — инкрементальная переиндексация (`/reindex` или кнопка
в админке): перевзвешиваются только изменённые документы. Для объектов
метаданных признаком изменения служит `configVersion` из `ConfigDumpInfo.xml`,
для markdown — sha1 содержимого.

## Архитектура

```
main.py              точка входа (desktop/web)
config.py            конфигурация из env, логирование, валидация
indexer/
  parser_1c.py       парсер XML-выгрузки: объекты, подсистемы, модули, карточки
  embeddings.py      e5-энкодер (префиксы query:/passage:, нормализация)
  store.py           FAISS (IndexFlatIP) + chunks.json + vectors.npy
  indexer.py         сборка индекса, инкрементальная переиндексация
mcp_server/
  server.py          FastMCP, 7 инструментов (stdio)
agent/
  llm_client.py      клиент DeepSeek (OpenAI-совместимый, thinking-режим)
  assistant.py       оркестратор: slash-команды + tool-calling цикл
ui/
  app.py             каркас: навигация, валидация конфигурации
  chat_view.py       чат: пузыри, markdown, быстрые команды
  admin_view.py      статистика, переиндексация, логи
  theme.py           палитра (оранжевый + серый, светлая тема)
data/                создаётся при работе: metadata_map.json, chunks.json,
                     vectors.npy, index_stats.json, assistant.log
```

Поток данных: XML-выгрузка → парсер → документы → эмбеддинги → FAISS.
UI держит постоянное MCP-подключение к серверу (stdio). Свободный вопрос →
DeepSeek → вызовы инструментов MCP → ответ со ссылками на источники.

## Перенос на VPS

1. Скопировать каталог `assistant-1c` и клонировать репозиторий выгрузки.
2. Установить зависимости и заполнить `.env` (ключ DeepSeek — только в env
   сервера, не в git).
3. `python -m indexer.indexer --full`, затем `python main.py --web --port 8550`.
4. За reverse-proxy (nginx) с базовой аутентификацией — у web-интерфейса
   собственной авторизации нет.
5. Пример unit-файла systemd:

```ini
[Unit]
Description=Assistant 1C
After=network.target

[Service]
WorkingDirectory=/opt/assistant-1c
EnvironmentFile=/opt/assistant-1c/.env
ExecStart=/opt/assistant-1c/.venv/bin/python main.py --web --port 8550
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## Замечания и ограничения

- Тексты модулей и документация при свободных вопросах отправляются фрагментами
  в DeepSeek (облако). Slash-команды ничего наружу не отправляют.
- Модель эмбеддингов работает локально на CPU; заменить её можно переменной
  `A1C_EMBED_MODEL` (размерность индекса при смене модели — пересоздать
  полной переиндексацией).
- `A1C_EMBED_BACKEND=hash` — только для автономных тестов без HuggingFace,
  качества поиска не даёт.
- Без `DEEPSEEK_API_KEY` UI запускается, slash-команды работают, свободные
  вопросы вернут ошибку о ключе.
- Если индексация пишет «выгрузка: .» или падает с «Error reading file
  'Configuration.xml'» — `A1C_DUMP_ROOT` не задан или не подхвачен. Проверьте,
  что `.env` лежит в корне проекта (рядом с `main.py`), а путь указан без
  кавычек, либо задайте переменную окружения.
- Если DeepSeek API отклоняет параметр thinking — поставьте
  `DEEPSEEK_THINKING=0`.
