# Финассистент

**Задача:** избавить себя от ручного переноса банковских операций в семейный
финплан Excel. Приложение читает PDF-справку Т-Банка «Движение средств»,
AI раскладывает операции по категориям вашего плана, дописывает суммы
в колонки «Факт» нужного месяца и даёт комментарий аналитика
(крупнейшие статьи, перерасход против плана, где можно сэкономить).

## Как участвует AI — и как не участвует

| Этап | Кто делает | Почему |
|---|---|---|
| Парсинг PDF → транзакции | код (`pdfplumber`) | детерминированно, без ошибок |
| Исключение внутренних переводов | код (шаблоны) | «Перевод себе» — не доход |
| Маскировка ПДн | код (регулярки) | до любого сетевого вызова |
| **Классификация операций по категориям** | **AI (DeepSeek)** | «OZON*123» → «Маркетплейсы» — это языковая задача |
| Суммирование, сверка | код | LLM не считает — числам он врёт |
| Запись в Excel | код (`openpyxl`) | дописывает `+сумма` к формулам-накопителям |
| **Комментарий аналитика + чат** | **AI (DeepSeek)** | выводы только по посчитанным агрегатам |

AI не создаёт и не изменяет ни одной цифры — только классифицирует
и комментирует.

## Приватность

- PDF **не покидает компьютер**: парсинг локальный, UI локальный.
- В LLM уходят только обезличенные строки: `26.09 | -1099.30 | Оплата в VKUSVILL`.
  Телефоны, номера договоров/карт/счетов, ФИО вырезаются кодом
  (`src/masking.py`). На вкладке «Разбор выписок» есть таблица
  «Что ушло в AI» — видно всё построчно.
- Остатки по счетам в LLM **не отправляются** вообще.
- Владельцы выписок — произвольные псевдонимы, которые вы вводите сами;
  в коде и поставке нет ничьих имён (`data/members.json` пуст по умолчанию).
- Вариант **C** (максимальная приватность): локальная модель через Ollama —
  данные вообще не уходят наружу (`CLASSIFIER_BACKEND=ollama`).

## Инварианты (проверяются кодом, не промптом)

1. AI не создаёт и не изменяет числа.
2. Категория — строго из закрытого списка строк шаблона; неизвестное →
   «Прочие расходы»/«Прочее» + список таких операций для ручной проверки.
3. Сверка: суммы по категориям + исключённые переводы == сумма выписки.
   Не сошлось → файл не выдаётся.
4. Внутренние переводы исключены из доходов/расходов **до** вызова LLM.
5. Дедупликация по хэшу файла: повторная загрузка той же выписки отклоняется
   (защита от двойного учёта). Для отладки есть **тестовый режим** (галочка
   на вкладке «Разбор выписок»): дедуп отключается на прогон, повторная
   обработка допишет суммы в Excel ещё раз — используйте только на копиях
   шаблона. Кнопка «Забыть обработанные файлы» очищает журнал хэшей
   (`data/processed_hashes.json`) — тоже позволяет загрузить файл заново.
6. Комментарий и чат строятся только на посчитанных агрегатах; обсуждение
   вложений — на уровне общих принципов, без обещаний доходности и без
   рекомендаций покупать конкретные бумаги; ответы про вложения снабжаются
   пометкой «Не является индивидуальной инвестиционной рекомендацией».

## Интерфейс: три вкладки

- **«Разбор выписок»** — выбор выписок (можно несколько сразу), у каждой —
  поле «Владелец» со свободным вводом псевдонима; форма остатков по счетам;
  итоги по статьям (Статья | Факт | План | Отклонение, кнопка «Копировать
  итоги» кладёт TSV в буфер — вставляется прямо в Excel); таблица
  обезличенных операций.
- **«Финансовый помощник»** — комментарий аналитика по итогам месяца и чат
  в контексте ваших цифр: «Где можно сэкономить?», «Топ-3 статей расходов»,
  «Куда вложить свободные средства?», «Что изменилось против плана?».
  История чата — последние 10 реплик, в контекст уходят только агрегаты.
- **«Логи»** — журнал работы: файлы, операции, инварианты, дубликаты, пути
  к результатам.

## Изменение шаблона финплана

**Какой файл править:** `data/template.xlsx` — он источник истины для
статей. Сам шаблон никогда не перезаписывается приложением: результаты
пишутся в новую копию в `output/`.

**После изменения статей** (добавили/переименовали строку в колонке C
листа «Финансовый план»):

```bash
python3 tools/rebuild_categories.py
```

Скрипт пересоберёт `data/categories.json` и `data/balance_rows.json`.
Ожидаемая структура листа: строка 2 — названия месяцев, строка 3 —
План/Факт, колонка A — секции («2. Доходы», «3. Расходы»…), колонка B —
подсекции вида «2.1.», колонка C — конечные статьи.

**Свой маппинг «операция → статья»:** добавьте в `data/template.xlsx`
лист **«Маппинг»**: колонка A — ключевое слово (нижний регистр, напр.
`vkusvill`), колонка B — статья финплана (точно как в колонке C).
Правила применяются **кодом, до вызова LLM**, — детерминированно:
DeepSeek не может их проигнорировать, токены на эти операции не тратятся.
В логах видно: «Маппинг: N правил, применено кодом к M операциям».

**Важно:** статья-цель правила обязана существовать в финплане
(колонка C листа «Финансовый план»). Если её нет — правило игнорируется,
а в логах красным пишется: «статья … не найдена в финплане — добавьте
строку в шаблон и запустите tools/rebuild_categories.py». Пример:
чтобы «Оплата в ОП Ростокино» → «Гимнастика» работало, сначала добавьте
строку «Гимнастика» в нужную подсекцию расходов, потом
`python3 tools/rebuild_categories.py`.

**Новый шаблон целиком:** можно, если сохранена структура выше (строки
месяцев, План/Факт, секции, лист «Финансовый план»). Проверка —
`python3 tools/rebuild_categories.py` должен отработать без ошибок,
затем `python3 tests/test_e2e.py`.

## Возможности

- **Мультизагрузка выписок**: несколько PDF за раз — операции объединяются,
  дубликаты файлов пропускаются с предупреждением, месяцы раскладываются
  по своим колонкам «Факт» автоматически.
- **Владельцы выписок**: каждому файлу — псевдоним владельца (свободный
  ввод). Если псевдоним совпадает с суффиксом статьи в шаблоне
  (напр. статья «% по вкладам Имя» и владелец «Имя»), персональные
  доходы попадают в «его/её» строки. Список псевдонимов можно задать
  в `data/members.json` — тогда классификатор видит только нейтральные
  категории + строки этого владельца. Пустой список = режим без привязки.
- **Графа «Доступный остаток»**: если в справке о движении средств она
  есть, остаток на конец периода по каждой карте автоматически попадает
  в форму остатков (записывайте в колонку следующего месяца как
  «Начальное сальдо»).
- **Остатки по счетам** (отдельная форма): справка об остатках парсится
  локально (в LLM не уходит), каждой позиции выбирается строка финплана
  (секции 1 «Начальное сальдо» / 5 «Конечное сальдо»), запись —
  **перезаписью** ячейки, так как остаток — снимок, а не оборот.
- **Экспорт в 1С** (включён по умолчанию, `EXPORT_1C=0` отключает): `output/1c_export_<месяц>.json` для базы
  «Целеполагание» — см. раздел ниже.

## Установка и запуск

### Windows (PowerShell)

```powershell
python -m venv venv
venv\Scripts\Activate.ps1
# если PowerShell запрещает скрипты активации:
#   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
pip install -r requirements.txt
python main.py          # десктопное окно
python main.py --web    # или в браузере на localhost:8550
```

### Linux / macOS

```bash
python3 -m venv venv && source venv/bin/activate   # или без venv
pip install -r requirements.txt
python3 main.py         # десктопное окно
python3 main.py --web   # или в браузере на localhost:8550
```

### Ключ API

`DEEPSEEK_API_KEY` читается из **переменной окружения ОС** (это основной способ):

```powershell
# PowerShell, только текущая сессия:
$env:DEEPSEEK_API_KEY = "sk-..."
# либо навсегда для пользователя Windows:
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-...", "User")
```

Файл `.env` (скопируйте из `.env.example`) — запасной вариант: переменная
окружения ОС имеет приоритет и не перекрывается файлом.

Без ключа приложение тоже работает: `CLASSIFIER_BACKEND=rules` —
офлайн-эвристика, комментарий шаблонный, чат отвечает заглушкой.

### Аудит запросов к LLM

`LLM_AUDIT=1` — в `output/llm_audit_*.json` сохраняется ТОЧНЫЙ текст каждого
запроса и ответа LLM. Можно открыть и глазами убедиться, что уходят только
обезличенные строки «дата | сумма | описание» и агрегаты.

## Интеграция с 1С «Целеполагание» (LifeProject)

Целевая точка — документ **ФинансовыйФакт** (табличная часть
«СтатьиДоходовИРасходов»: Показатель / Сумма / Валюта; структура проверена
по выгрузке конфигурации).

**Вариант D (готов, файловый обмен):**
1. Здесь: при прогоне автоматически пишется `output/1c_export_<месяц>.json`
   (по умолчанию включён; `EXPORT_1C=0` в `.env` отключает).
2. В 1С: вставьте код из `1c/Module_ЗагрузкаФинФакта.bsl` в вашу обработку
   «ЗагрузкаБанковскойВыписки», укажите путь к JSON — создаётся/перезаписывается
   документ «ФинансовыйФакт» за месяц; неизвестные статьи создаются
   в справочнике «ФинансовыеПоказатели» внутри групп Доходы/Расходы.

**Варианты на вырост:** C — COM-коннектор (Windows + платформа, без
веб-сервера); B — HTTP-сервис в расширении конфигурации; A — встроенный
OData при публикации базы. Прямая запись в .1CD/SQL минуя платформу —
запрещена (закрытый формат, служебные GUID).

## Структура

```
main.py                    Flet UI «Финассистент» (3 вкладки, серый + оранжевый)
src/
  parser_tbank.py         PDF выписки -> DataFrame (текстовая стратегия)
  parser_balances.py      PDF справки об остатках -> позиции остатков
  masking.py              маскировка ПДн перед LLM
  categories.py           таксономия, владельцы, лист «Маппинг»
  classifier/
    base.py               интерфейс + валидация ответа
    deepseek.py           DeepSeek API (t=0, JSON, батчи, подсказки маппинга)
    rule_based.py         офлайн-эвристика (маппинг + fallback)
    ollama_local.py       вариант C: локальная модель
  aggregator.py           суммы по месяцам + инварианты + дедуп
  excel_writer.py         дописывание «Факт» в копию шаблона, остатки
  advisor.py              комментарий аналитика + чат (LLM | rules)
  export_1c.py            JSON-экспорт для 1С
  pipeline.py             оркестрация
tools/
  rebuild_categories.py   пересборка categories.json из шаблона
1c/
  Module_ЗагрузкаФинФакта.bsl   код загрузки JSON в 1С
data/template.xlsx        шаблон финплана (источник истины, не перезаписывается)
data/categories.json      таксономия (генерируется из шаблона)
data/members.json         псевдонимы владельцев (пусто = без привязки)
data/balance_rows.json    строки остатков (генерируется из шаблона)
output/                   обновлённые файлы, экспорты 1С, аудит LLM
```

## Ограничения MVP (честно)

- Только Т-Банк, только текстовая PDF-справка (не скан). Другие банки —
  свой парсер на том же интерфейсе.
- Внутренние переводы на брокерские договоры исключаются из расходов,
  но пока не заполняют строки «Пополнение ИИС» — вручную.
- Персональные строки доходов работают через суффикс в названии статьи
  (см. «Владельцы выписок») — это соглашение шаблона, а не магия.
