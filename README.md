# Код-ассистент 1С (эксперт-разработчик)

AI-ассистент, который **выполняет реальные операции с файлами проекта**, а не
только отвечает текстом. Развитие проекта `assistant-1c` (тот — read-only:
RAG, просмотр структуры, git diff) вынесено в отдельный проект: здесь
ассистент **читает, ищет, анализирует и изменяет** файлы XML-выгрузки
конфигурации 1С и пишет документацию.

Роли: пользователь — **аналитик**, ставит задачи на уровне цели
(«найди, где используется X», «задокументируй изменения по модулю Y»);
ассистент — **эксперт-разработчик 1С**, сам решает, какие файлы читать
и что менять. LLM — DeepSeek (`deepseek-v4-pro`), ключ из переменной
окружения `DEEPSEEK_API_KEY`.

## Реализованные сценарии

| Сценарий | Как работает |
|---|---|
| Найти все места использования компонента/API | `search_files` (подстрока/regex) по всем файлам выгрузки с контекстом |
| Создать/обновить документацию по коду | `read_file`/`search_files` → `write_file` в `docs/` |
| Подготовить diff, не записывая | `write_file` / `append_to_file` с `dry_run=true` |
| Проверка инвариантов | guard-слой в коде + тесты `tests/` |

Каждая доработка автоматически попадает в раздел «Журнал доработок»
`README.md` рабочей директории (реализовано кодом, не промптом).

## Инварианты (гарантируются кодом, см. `agent/guard.py`)

1. Работа **только** внутри рабочей директории (`CA1C_WORKSPACE_ROOT`,
   у аналитика — `C:\AI Advent\Week 7\LifeProgect`). Абсолютные пути,
   `../..`, симлинки наружу — отказ (`GuardError`).
2. `.github` — **read-only**: чтение можно, запись отклоняется.
3. **Удаления не существует**: инструмента удаления нет в наборе вообще.
4. Перезапись существующего файла — только после **подтверждения аналитика**
   (в консоль выводится действие и diff). Создание новых файлов — свободно.
5. Перед неоднозначными/опасными действиями ассистент обязан посоветоваться
   с аналитиком — инструмент `ask_analyst`.

Попытка LLM нарушить инвариант возвращается ей как отказ инструмента —
модель видит причину и работает дальше в рамках правил.

## Установка и запуск

```bash
cd code-assistant-1c
python -m venv .venv
.\.venv\Scripts\Activate.ps1      # Windows PowerShell
# source .venv/bin/activate       # Linux/macOS
pip install -r requirements.txt

cp .env.example .env              # и заполнить:
#   DEEPSEEK_API_KEY=...
#   CA1C_WORKSPACE_ROOT=C:\AI Advent\Week 7\LifeProgect
```

Если `DEEPSEEK_API_KEY` уже задан в переменных окружения — в `.env`
дублировать не нужно. Модель меняется переменной `DEEPSEEK_MODEL`
(по умолчанию `deepseek-v4-pro`; дешевле для агентных циклов —
`deepseek-flash`; алиасы `deepseek-chat`/`deepseek-reasoner` выведены
из эксплуатации 24.07.2026 и не работают).

```bash
# По умолчанию — UI (Flet): чат аналитика с разработчиком, журнал, админ
python main.py                       # десктопное окно
python main.py --web                 # браузер, http://localhost:8550

# Консоль: интерактивный режим (задачи одна за другой, с подтверждениями)
python main.py --cli

# Консоль: одна задача
python main.py "Найди, где используется Справочник.ФинансовыеПоказатели, и выпиши в docs/"

# Другая рабочая директория / консоль без подтверждений (рискованно)
python main.py --workspace "D:\other\dump" --cli --yes
```

**Если при запуске UI `ModuleNotFoundError: No module named 'flet'`**: flet
установлен не в тот интерпретатор, из которого идёт запуск (частая ситуация:
пакеты поставлены в `.venv`, а запуск — из системного Python, или наоборот).
Активируйте venv и ставьте зависимости в него:

```powershell
.\.venv\Scripts\Activate.ps1          # в промпте появится префикс (.venv)
pip install -r requirements.txt
python main.py                        # запуск из того же venv
```

Проверить, какой интерпретатор реально используется: `python -c "import sys; print(sys.executable)"`.
Рантайм-пакеты `flet-web` и `flet-desktop` включены в `requirements.txt` —
ничего доустанавливаться при первом запуске не должно. Не полагайтесь на
авто-доустановку flet: без активного venv она падает с ошибкой
`No virtual environment found`.


## Интерфейс (светлая тема в цветах 1С: жёлтый #FFF200 + красный #E2001A)

| Страница | Что делает |
|---|---|
| **Чат** | Диалог аналитика с разработчиком: задача на уровне цели, ход работы (вызванные инструменты), финальный ответ. Перезапись файла — модальный диалог с diff и кнопками «Подтвердить/Отклонить»; вопросы ассистента — диалог с полем ответа. |
| **Журнал** | В какие файлы внесены изменения: время, тип (создан/перезаписан/дописан/отклонено), путь, описание доработки, diff по клику. Источник — `data/changes.jsonl`, который FileTools пишет при каждой записи. |
| **Админ** | Конфигурация (модель, workspace, ключ), статус директории (выгрузка, git, docs/, README), инварианты, статистика журнала, команды проверки. |

Ядро ассистента синхронное и работает в фоновом потоке; подтверждения
и вопросы маршаллятся в UI-поток как модальные диалоги — до решения
аналитика рабочий поток заблокирован, семантика «советоваться с человеком»
в UI та же, что в CLI.


## Воспроизводимость без API-ключа

```bash
python demo.py        # агентский цикл на моке LLM: поиск использований,
                      # документация в docs/, журнал README, отклонение
                      # попыток писать за workspace и в .github
python -m pytest tests/ -q   # 26 тестов: инварианты, инструменты, цикл
```

Демо создаёт временный мини-проект (XML + bsl), прогоняет сценарий
«найди использования и задокументируй» и показывает: вызванные инструменты,
журнал README, дерево файлов после работы. Удаление временного каталога
делает сам демо-скрипт — у ассистента операции удаления нет.

## Инструменты ассистента

| Инструмент | Назначение |
|---|---|
| `list_files` | Дерево файлов проекта (имена `#U0424…` показываются кириллицей) |
| `read_file` | Чтение файла построчно (offset/limit) |
| `search_files` | Поиск подстроки/regex по содержимому нескольких файлов |
| `write_file` | Создать/перезаписать файл; diff; подтверждение; `dry_run` |
| `append_to_file` | Дописать в конец (changelog, ADR-лог); подтверждение; `dry_run` |
| `ask_analyst` | Вопрос человеку-аналитику с ожиданием ответа |

## Архитектура

```
main.py              точка входа: --ui / --web (Flet) или CLI
config.py            конфигурация из env, валидация
agent/
  assistant.py       агентский цикл function calling (задача -> инструменты -> ответ)
  prompts.py         системный промпт эксперта-разработчика 1С
  llm_client.py      DeepSeek (OpenAI-совместимый API, thinking-режим)
  fs_tools.py        файловые инструменты + авто-журнал README + JSONL-журнал
  guard.py           инварианты: workspace, .github read-only, нет удаления
  mock_llm.py        мок LLM для демо и тестов без ключа
ui/
  app.py             каркас: шапка 1С, навигация Чат/Журнал/Админ
  theme.py           светлая тема, фирменные цвета 1С (жёлтый + красный)
  chat_view.py       чат, диалоги подтверждения (diff) и вопросов аналитику
  logs_view.py       журнал изменений файлов с diff
  admin_view.py      конфигурация, статус, инварианты, статистика
data/                создаётся при работе: changes.jsonl
demo.py              воспроизводимый прогон без API-ключа
tests/               тесты инвариантов, инструментов и агентского цикла
```

Почему без MCP: в `assistant-1c` MCP нужен для read-only доступа к кэшу
индекса из отдельного процесса. Здесь инварианты записи надёжнее держать
в одном процессе с инструментами — function calling + локальные функции
(тот же паттерн, что у Codex CLI / Claude Code).

## Ограничения

- Содержимое файлов, которые ассистент читает, фрагментами уходит в DeepSeek
  (облако) — как и в `assistant-1c` при свободных вопросах.
- Ассистент правит XML-выгрузку, а не базу: после его доработок выгрузку
  нужно загрузить в конфигуратор и проверить — об этом он напоминает
  в финальном ответе.
- `--yes` отключает подтверждения — используйте только на копии проекта
  или под git.
- Рекомендуется держать рабочую директорию под git: тогда любые правки
  ассистента дополнительно видны через `git diff` и откатываются.
